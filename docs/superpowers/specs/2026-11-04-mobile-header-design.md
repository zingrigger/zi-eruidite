# 手机顶栏：两行布局设计

日期：2026-11-04
状态：已批准（2026-11-04）
范围：`< 64rem` 的全局顶栏；中文首页为验证起点，改动对所有页面生效

## 1. 为什么

手机上的顶栏现在是把桌面侧栏硬折成一行：六个导航项挤在约 175px 里，中文被逐字断行；整条实际高 90px，而 `--bar-nav-height` 仍按约 50px 计算，导致文章页吸顶 TOC 有 40px 压在栏下。320px 下右侧操作区还会出屏（右缘 361 > 320）。

目标是让手机顶栏一眼可读、每项可点、条高稳定，并且中文/英文都成立；不引入框架、不新增交互层。

## 2. 方案取舍

在 360px 宽的真实导航项下比较过四种走法：

- **A · 两行**（选定）：第一行品牌 + 操作，第二行六个栏目均分。全部可见、零新交互、不改信息架构；代价是顶栏约 96px，与现在差不多高，未来再加栏目会放不下。
- **B · 主项 + 更多**：单行 52px，只留博客/动态/收藏板，其余进 popover。主次分明、可扩展；代价是三项多一次点击，并新增一个浮层。
- **C · 横滑**：单行 52px，六个栏目横滑。零新界面；但收藏板/作者默认在屏外，横滑会和 iOS 返回手势冲突。
- **D · 汉堡菜单**：单行 52px，全部收进抽屉。最干净；但所有栏目都多一次点击，还多一层遮罩。

选 A 的原因：用户明确倾向“全部可见、不藏”，且现有六项在 328px 最小内容宽下中英文都放得下（英文六项 14px 合计约 254px，328px 下还剩约 8px 间距）。A 不改变导航信息架构，也不引入新的运行时。

## 3. 设计

### 3.1 两行结构（仅 `< 64rem`）

`site-bar` 从单行 flex 改为两行 grid；`bar-inner` 在手机端 `display: contents`，让品牌、导航、操作成为同一网格的子项：

```text
┌──────────────────────────────────────┐
│ [logo] 站名(≥26rem)       [主题] [EN] │  52px
├──────────────────────────────────────┤
│ 博客   动态   标签   项目   收藏板  作者 │  44px
└──────────────────────────────────────┘
```

- 第一行：沿用现有品牌簇（logo；站名仍只在 `≥ 26rem` 显示）、主题切换、语言切换。**手机端隐藏小眼睛与布局切换**：触屏没有指针，眼睛只是静态装饰；布局切换在手机上只剩内容换皮，收掉后不再让桌面偏好影响手机视图。文章页的全宽按钮同样隐藏（它在 50rem 以下没有实际效果）。
- 第二行：六个栏目均分，`font-size: var(--step--1)`（约 14px），行高 44px，`white-space: nowrap`，`justify-content: space-between`。当前栏目的 `aria-current="page"` 继续用前景色标出；系列子级面包屑继续隐藏。
- 两行之间加一条极淡的 1px 虚线（`color-mix(in oklab, var(--border) 45%, transparent)`），与顶栏既有的虚线语言一致；底边沿用各布局现有边框，不新增第二种视觉语言。
- `≥ 64rem` 的 sidebar / topbar 结构完全不动。

### 3.2 高度与滚动偏移

- 第一行 52px + 第二行 44px，整条约 96px。
- 手机端 `--bar-nav-height` 与顶栏实际高度共用一个来源，不再各自推导；顶栏按该 token 固定高度，TOC 的 `top` 与 `scroll-padding-block-start` 继续读同一个值。验收时实际条高与 token 误差 ≤1px。
- `site-bar` 在两个布局下都保持 `position: sticky; top: 0`，两行一起吸顶。

### 3.3 中英文

- 导航文案继续走 `t(locale, key)`，不写死。
- 已量：IBM Plex Sans 14px 下英文六项约 254px；328px 内容宽（设计系统最小视口）下剩余约 8px 间距，320px 下约 7px，不溢出。
- 英文 `Moments` 是最宽项（约 59px）；不做截断、不换行。

### 3.4 无障碍

- 每个导航项的可点高度 44px；焦点环沿用全局 `:focus-visible`。
- 隐藏的小眼睛不进入 tab 序；布局/全宽按钮隐藏后不留下空焦点。
- 不新增 JS、不新增弹层，因此不引入焦点陷阱或滚动锁。

## 4. 非目标

- 不重排首页 hero、文章列表或文章页 TOC（下一块单独定）。
- 不统一手机端 sidebar/topbar 的内容样式；本次只统一顶栏结构。
- 不改桌面顶栏/侧栏，不改导航信息架构。
- 不新增“更多”菜单、抽屉、横滑或任何框架依赖。

## 5. 验收

- 320 / 328 / 360 / 390 / 430 宽，zh 与 en，sidebar 与 topbar 两种布局：
  - 六个栏目单行可见，无横向滚动；
  - 顶栏实际高度与 `--bar-nav-height` 误差 ≤1px；
  - 文章页吸顶 TOC 顶边紧贴顶栏，不再被压住；
  - 桌面（≥64rem）截图与改动前一致。
- `npm run format:check`、`npm run build`、`bash scripts/tests/i18n-check.sh` 通过。
- 保留 `scripts/tests/home-guide-topbar-check.sh` 的现有断言（home-rails / home-rule 不受影响）。
